# 1.2.6 登录修正

1.2.5 的反馈说明自动认证仍会等待过久；旧版打开官方认证的入口在忙碌时消失，网页认证后又要等学期和课表，容易把同步失败看成登录失败。

本次对照两版源码，并以匿名 GET 检查学校公开的 SSO 跳转、手机认证页及其脚本。没有提交真实账号或密码，也没有运行应用。

## 页面与流程

填写学号与密码后，只核验学校身份。成功便返回应用，再读取真实学期和课表。验证码或账号安全提示需要在官方页面处理；用户可以在等待时取消，或直接切换官方认证。原输入、缓存和手动课程保留。

密码只留在 ViewModel 和本机加密存储，不写入保存界面的 Bundle。旋转页面可继续观察同一项后台任务；进程被关闭后，重新打开页面会提示重试。账号变更时重新匹配记住的密码，用户正在输入的其他密码不会每次被覆盖。

旧版官方页面补上原生玻璃菜单。打开网页前先取消并等待隐藏认证任务结束，避免两个 WebView 同时修改学校会话。进入 CAS 页面时不轮询学生接口；实际回到教务页面后才做有限的身份确认。认证成功后，网页返回和课表同步各自完成。

## 请求与协议

学校 SSO 返回的完整 `service` 回调继续沿用。公开的 H5 页面是 Vue / iView 组件，没有 HTML form；密码处理包含学校自己的加密、账号安全检查与跳转。因此继续调用已确认页面的官方登录按钮，不猜测密码接口。

隐藏 WebView 按屏幕尺寸布局，并使用仅限已确认 CAS 面板的后台适配。原先的可见区域判断在未附着窗口的页面上可能不成立；这是从源码与页面布局得出的判断，尚未在手机上复现。控件数量、域名、服务地址和学生身份匹配仍须通过校验。

学生身份请求上限为 12 秒，自动认证总等待上限为 55 秒；请求采用可取消的 OkHttp 回调，取消会关闭连接。验证码、安全提示、账号错误和连接失败分别处理。回调错误时仅尝试一次实际教务首页，仍必须通过学生接口确认，网页加载成功本身不算登录成功。

## 本次验证范围

源码诊断、学校公开资源检查与编译结果分别记录。APK 的签名、版本、源资产、ABI、对齐、凭据明文扫描和发布收据见 [验证记录](../VERIFICATION.md)。按用户要求，本轮不连接手机、不运行应用功能或性能测试，因此不宣称真实自动登录、验证码交接和键盘布局已经通过实机验证。

Android 对 WebView 渲染进程退出的处理依据 [官方文档](https://developer.android.com/develop/ui/views/layout/webapps/managing-webview)：销毁不可用实例，并允许重新创建页面。
