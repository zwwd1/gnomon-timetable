# Gnomon 1.2.12 更新说明

2026-10-15。按本轮优化资料包开发，只修改 Gnomon，Lumen 保持原样。用户随后要求上传 GitHub，本版按该授权同步源码、安装包与更新清单。原包名 `cn.scvtc.campus.preview` 和签名保持，支持符合版本条件的覆盖安装。

## 本轮改动及依据

| 问题 | 本地代码中确认的原因 | 改动 |
|---|---|---|
| 成绩、教务切换后底栏消失 | FloatingDock 直接启动 Activity，根导航只有 Home/Config | 为 Grades/Sync 建立独立根身份，共用主宿主与底栏；抽出原 AcademicContent，旧 Intent 只交接主宿主 |
| 切回页面丢状态、隐藏页可能挡触摸 | 页面离开后卸载；留存页只控制绘制和 alpha | 首次访问后留存，隐藏时不放置子树；转场退出期隔离旧页输入；切页清除搜索焦点 |
| 底栏入口变化后选中和拖动范围不一致 | 整组 key 销毁动画；remember 闭包保存旧数量、宽度和回调 | 按稳定 ID 保留项目，宽度动画、最新回调与数量/范围同步，小幅拖动仍吸附整数项 |
| 调休入口等待或结果交接不明确 | 页面等待的 loaded 依赖活动课表和非空作息，并非所编辑的目标课表；回传未核对草稿 | 目标配置存在即可编辑，结果核对课表 ID 和原草稿，启动失败显示原因，沿用原 ActivityResult/父页保存链 |
| 作息缺时间时打开后无法补填 | 时间轴过滤无法解析的节次，只给已有效的时间块提供编辑入口 | 按配置节次补齐空字段，沿用时间选择和父页草稿；完整作息仍使用原拖动时间轴；保存校验，不编造时间 |
| 只有单项玻璃滑杆 | 单一首页模糊倍数，没有分材质配置和编辑事务 | 扩展现有本机偏好为三套材质，预览和已保存值分离；恢复默认只改当前套，应用才写入 |
| 恢复默认按钮贴边 | 按钮直接作为组内子项，缺少操作区边距 | 与设置行统一 14dp 水平边距及底部留白 |
| AI 字段挤压且 Key 明文编辑 | Gnomon 使用紧凑右侧输入 | 连接字段使用标签与独立全宽原生 Miuix 输入，Key 默认遮掩并可显示；加密和退出保存链保持 |

截图 01 的“AI 服务配置 / 加密保存”组件经全工作区搜索实际位于 Lumen，Gnomon 的真实入口是“设置 → AI 设置”。本轮不改 Lumen，不移植另一套 AI 功能或另造同名弹窗；优化的是 Gnomon 当前这套配置。

以上是源码条件与修复说明，不等于在用户手机复现了每一种点击故障。

## 三种玻璃

入口：设置 → 通用设置 → 玻璃材质。上方为实时渲染预览，可点底栏切页，也可预览真实缓存的成绩控件。预览不自动请求学校数据。使用当前壁纸来源；没有壁纸时使用主题背景。

共用参数：模糊半径 dp、不透明度 %、着色 %、圆角 dp、高光 %、描边 dp、阴影半径 dp。

- 液态：背景采样、透镜折射高度/强度 dp、色散、按压形变和回弹响应。
- 高斯：背景模糊和着色，明确不执行透镜或色散。
- 柔光：背景模糊后调整亮度、对比、饱和度，并使用静态像素纹理和柔和混色；不是系统私有引擎。

复用已有 Backdrop 引擎，没有增加第二套捕获或新依赖。作用于本轮底栏、选中胶囊、按钮、设置分组/弹层和成绩控件；课程卡片颜色、文字和已有光学参数不变。蓝色确认与红色危险按钮保留语义颜色以保证文字可读。旧用户未应用新材质前继续使用原渲染参数；无需清库迁移。

预览值尚未应用时，取消恢复进入时的值；系统返回提示处理草稿；直接关闭页面也不写入未应用值。主题变化不会覆盖材质选择。静止没有新加永久逐帧循环。

## 时间与旧数据

不改数据库版本、作息和调休格式。学校同步与本地编辑的写入保护沿用 1.2.11。日/周、提醒与组件继续使用既有 `coursesForDate`、调休原教学日规则和实际作息解析；不新增另一份假期表，不把公共调休工作日自动解释成本校补课日。

调休仍为父页草稿：子页取消不回传，确认后只修改草稿，最终保存由原详细设置提交。时间缺失补填也是草稿操作。已有自定义时间、其他作息和原教学日映射保留。

## 检查与限制

Release 构建、R8、lintVital、原签名、资源与原生库保留、16 KiB 对齐及源码对应核对通过。21 项定向规则检查通过：缺失时间 2 项、调休 16 项、三套材质保存 3 项。未连接手机；没有把附件静态图当作点击、流畅度、键盘、旋转、预测性返回或 Android 17 的验收证据。没有执行安装、清除数据或学校账号联调。

本轮未引入 WebDAV、Shizuku、KMP 或截图中的演示数据。后续若接 WebDAV，可沿用现有备份解析→预览确认→原子恢复流程，并将凭据放入现有加密存储，与学校认证隔离。
